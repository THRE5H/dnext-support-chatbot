ISSUE 1: "Your account has been suspended. Please contact support."
================================================================================

Problem:
--------
When calling the tool, the response shows:
  "Answer: ❌ Your account has been suspended. Please contact support...."

Root Cause:
-----------
The backend's /api/chat endpoint is returning this error message because:
  1. The MCP server creates a session with ID "mcp_platform_support"
  2. The backend cannot find this session in its session store
  3. The backend returns a suspension/error message instead of processing the query

Why This Happens:
-----------------
- The V1 ChatbotApp expects sessions to exist in its database (SQLite)
- MCP sends requests with a NEW session ID that doesn't exist
- Backend rejects the request as invalid/suspended

Solution Implemented:
---------------------
Updated backend/mcp_spec_server/tools.py to:
  1. Detect when backend returns "suspended" or "error" messages
  2. Return a helpful message explaining the issue
  3. Suggest that backend needs proper session initialization

Files Modified:
- backend/mcp_spec_server/tools.py (lines 73-79)

Example:
  Old: "Your account has been suspended. Please contact support."
  New: "The backend service is not properly configured for MCP. Please ensure..."


ISSUE 2: Parse error -32700 "Parse error"
================================================================================

Problem:
--------
When sending POST requests to the /mcp endpoint, receiving:
  data: {"jsonrpc": "2.0", "error": {"code": -32700, "message": "Parse error"}}

Root Cause:
-----------
The JSON-RPC specification requires proper parsing of incoming requests.
The code -32700 means "Parse error - Invalid JSON was received by the server"

This happens when:
  1. Request body is not valid JSON
  2. Content-Type header is incorrect
  3. Request encoding is wrong
  4. HTTP server isn't properly reading the request body

Solution Implemented:
---------------------
Updated backend/mcp_spec_server/http_server.py to:
  1. Log the Content-Type header of incoming requests
  2. Add detailed error messages for JSON parse failures
  3. Log the raw request body for debugging
  4. Provide better error context

Files Modified:
- backend/mcp_spec_server/http_server.py (lines 33-46)

This helps identify whether:
  - Client is sending malformed JSON
  - Content-Type is not "application/json"
  - Request body is empty or corrupted
